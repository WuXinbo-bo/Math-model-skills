# 模型质量与逐问递进合同

本合同用于把多个子问题组织为同一条研究主线。它不规定固定算法，也不增加新的交付物；所有记录写入现有 `建模报告.md` 与 `图表/全部结果.json`。

## 1. 统一机制内核

先识别跨问题复用的核心机制，例如状态方程、守恒关系、几何判据、统计生成过程、供需平衡或资源网络。核心机制只完整建立一次，后续问题通过继承和增量修改扩展，禁止逐问重新包装一组互不关联的模型。

机制内核必须回答：

- 研究对象及状态如何表示；
- 对象之间通过何种方程、集合、图结构或概率关系连接；
- 有效事件、可行状态或预测结果如何判定；
- 输入、输出、单位、定义域和适用边界是什么。

## 2. 模型语义卡

`new_model` 与 `model_extension` 在原有模型定义和结构卡后增加一行：

```text
模型语义 QN | 目标数量: 0/1/2... | 目标方向: none/min/max/min,max... | 变量类型: continuous/integer/binary/mixed/state | 关系类型: linear/nonlinear/differential/stochastic/geometric/simulation/hybrid | 多目标证据: not_applicable/冲突目标及聚合或 Pareto 证据
```

- 非优化模型可使用 `目标数量: 0` 与 `目标方向: none`，但仍须说明统计关系、状态方程或判定机制。
- 多资源、高维变量或多个评价指标不等于多目标优化。只有两个以上需要同时优化且存在冲突或明确聚合关系的目标，才可使用“多目标”模型名。
- 算法不能替代关系类型。PSO、SQP、遗传算法、HiGHS、匈牙利算法等只进入求解算法字段。

## 3. 增量模型卡

`model_extension` 另增加：

```text
模型增量 QN | 继承方程: ... | 新增变量: ... | 新增/修改约束: ... | 目标变化: ... | 求解变化: ... | 验证变化: ...
```

新增内容必须对应题目新增要求。仅更换求解器、调参或增加迭代次数不构成模型扩展。

## 4. 可复用组合模式

按题目证据按需选择，不得机械套用：

- 物理/几何题：统一坐标或状态空间 -> 对象状态方程 -> 相互作用/可见性判据 -> 事件边界 -> 外层优化。
- 事件集合题：状态指示函数 -> 边界粗定位 -> 根求解或二分精化 -> 有效区间集合 -> 并集、交集、重叠和边际贡献。
- 多资源题：单资源基线 -> 联合目标 -> 容量/冲突约束 -> 边际贡献与闲置检查。
- 混合决策题：离散分配/路径/调度层 -> 连续控制或参数层 -> 一致性回代；分层是建模结构，不意味着固定使用某种算法。
- 非凸优化题：可行基线 -> 全局探索 -> 可选局部精化 -> 多随机种子与约束残差；必须报告每层真实增益。

## 5. 差异化验证

每次模型扩展必须验证新增机制，而不是重复上一问的同一种灵敏度图：

- 新增时序约束：检查先后关系、间隔和事件边界精度；
- 新增资源：检查独立贡献、增量贡献、重叠和闲置；
- 新增分配层：检查容量、覆盖、匹配稳定性和分配后连续决策可行性；
- 新增随机/鲁棒机制：检查情景外表现、可行率和代价；
- 新增近似或采样：检查网格、步长或样本量收敛。

“灵敏度较小”只说明局部参数响应，不能单独证明正确性、稳定性或鲁棒性。灵敏度报告必须给出定义、扰动范围、固定决策还是重新优化、可行率、变化方向和异常点。

## 6. 发布声明

在现有 `图表/全部结果.json` 中使用 `publication_claims` 登记进入摘要、正文、表格或结论的关键数值，不新增结果文件：

```json
{
  "publication_claims": {
    "C-Q1-01": {
      "question": "Q1",
      "statement": "最优方案的总有效时长",
      "display_value": "6.403 s",
      "source_key": "Q1.metrics.total_effective_duration",
      "derivation": "interval_union",
      "required_in": ["body", "table"]
    }
  }
}
```

同一声明在摘要、正文、图表和结论中必须来自同一 `source_key`。加总、区间并集、均值、比率等派生量必须声明 `derivation`，禁止人工改写产生数值冲突。
