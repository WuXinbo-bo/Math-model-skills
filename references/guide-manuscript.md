# MANUSCRIPT · 竞赛文稿集成

- 实施协议：`references/stage_protocols/manuscript-synthesis/SKILL.md`
- 关键交付物：PDF 路线为 `论文/论文正文.tex` 与 `论文/章节/*.tex`；DOCX 路线为 `论文/论文正文.md`
- 核验点：`approve`

## 主控职责

- 从指定模板启动，不徒手重建整套 LaTeX 结构。
- 按 `output_format` 选择唯一主路线；DOCX 使用当前赛制 Markdown 模板，禁止同时另造一套内容不同的 LaTeX 正文。
- 集成问题契约、模型机制、程序结果、图形资产、参考文献和附录。
- 在闭合前清除占位符并核对模板完整性。

## 实施角色

- `paper-writer`：组织完整中文竞赛文稿。
- `format-checker`：核对章节、模板、图形、表格与正文完整性。

## 审计重点

- 论文陈述务必与上游证据保持一致。
- 全部产出图形和引用标签务必转入正文。
- 图表嵌入时必须按版心缩放：LaTeX 普通图默认 `0.72\linewidth × 0.70\textheight`，普通宽图建议不超过 `0.85\linewidth`，任何图均不得超过 `\linewidth`，并启用 `keepaspectratio`；DOCX 不超过页面可用正文宽度，常规 A4 推荐 13.5--15.0 cm。
- 页数限制是上限而非目标。接近上限时先压缩空白、重复图表和冗余表达，必须保留逐问的模型机制、推导、结果、验证和解释；正文不足时禁止用放大图片或套话补页。
- 摘要、关键词、结论、参考文献与程序附录不可缺失。摘要读取论文表达卡，用自然语言逐问写简洁模型名或继承关系、核心方法、关键结果和检验；不得逐字抄写审计身份卡，不得使用“标准模型族为”或内部工作流术语。关键词使用模型族或核心算法。
- 有真实数据时在“模型准备”中独立说明数据来源、实际预处理、处理前后质量、泄漏控制和冻结输入；无数据时只保留真实豁免说明。
- 使用 `工具/build_code_appendix.py` 从 `程序/code_manifest.json` 生成真实代码附录；三种赛制均只嵌入主程序和逐问核心实现，辅助源码只列清单，论文显示名统一为英文代码名。
- CUMCM 模板不得生成目录；必须保留 `AbstractStart/AbstractEnd` 与 `BodyStart/BodyEnd` 页码标签，实际编译后验收摘要 1 页和正文 30 页上限。
